**Status:** D1, D2 and D3 (cabinet FIR, integrated in the chain, timing met) implemented and verified in simulation; D4–D5 blocks in development; board test at the end of step D.

## D1: generated LFO

### Today

The tremolo reads one of **8 ROM tables** (8-bit, 0..254), one per waveform and
rate: sine 5 / 7 / 10 / 12 / 15 Hz, triangle 5 / 10 Hz, saw 10 Hz. Each table holds
one period (9600 … 3200 entries), stepped once per sample. Together they use
535 kbit and about 70 M10K blocks. Only these 8 combinations exist, the
resolution is 8 bits (a one-pole filter in the tremolo hides the steps), and
changing the waveform jumps to another table's phase.

The chorus has its own triangle counter that moves the delay by whole samples
(fixed in D2).

### New block: `nco_lfo`

```
rate (0.01 Hz) ──► × K ──► inc (32 bit)          once per sample (tick):
                                  │                phase += inc
                                  ▼
                       phase accumulator (32 bit) ──┬─► sine:   quarter-wave table 256 × 16 bit
                                                    │           + linear interpolation (next 8 phase bits)
                                                    ├─► triangle: |2·phase − 1| (no table)
                                                    ├─► saw:      rises over 95 %, ramps down over 5 % (as the v1 table)
                                                    └─► square:   phase MSB
                                                           │
                                                 lfo (unsigned 16 bit, 0 .. 65535)
```

* **Frequency:** `inc = rate · 2^32 / (100 · 48000)`, computed as
  `(rate · 916 260) >> 10`. `rate` is in 0.01 Hz, so 1 … 2000 = 0.01 … 20 Hz.
  Resolution 11 µHz (48000 / 2³²): 5 Hz comes out as 4.999995 Hz (the old 7 Hz
  table was 7.0001 Hz).
* **Sine:** one quarter-wave table of 256 × 16-bit words (a single M10K, or logic),
  generated by a VHDL function at elaboration (no `.mif`). The next 8 phase bits
  interpolate linearly between entries: ~16-bit smooth sine, max error
  6.4·10⁻⁵ of full scale (2 LSB at 16 bits).
* **Triangle / saw / square** are arithmetic on the phase (no memory).
* **Output:** unipolar 0 … 65535, like today's tremolo LFO after its smoothing
  (0 … 65280). The phase is continuous: changing the rate never jumps.
* **Edges:** the square has hard steps (the saw ramps down over 5 % of the period);
  the existing one-pole filter in the tremolo (τ = 32 samples, 0.7 ms) stays and
  rounds them.
* Cost: one 16 × 20-bit multiply (rate → inc, could also be a 2-cycle shift-add),
  a 32-bit adder, one table, one interpolation multiply. Same strobe timing as
  the effects (multicycle).

### Registers

Backward compatible: `trem_wave` values 0–7 keep their meaning, so the presets
and `gme_hps.py` keep working.

| Reg | Name | Change |
|-----|------|--------|
| 3 | Tremolo Wave | bits `[2:0]`, bit 3 = 0: **legacy presets** as today (0–4 sine 5/7/10/12/15 Hz, 5–6 triangle 5/10 Hz, 7 saw 10 Hz), now produced by the LFO. Bit 3 = 1: **free mode**, bits `[1:0]` = shape (0 sine, 1 triangle, 2 saw, 3 square), rate from TREM_RATE |
| **0x16** | **TREM_RATE** (new) | LFO rate in 0.01 Hz (free mode), e.g. 450 = 4.5 Hz; smoothed like the other parameters |

VERSION becomes `0x0203`. `gme_hps.py` gets `set trem_shape=… trem_rate=4.5`.

### What changes in the sound

* The legacy presets sound the same: same shapes and rates, smoother (16-bit
  instead of 8-bit, no table steps). Waveform changes no longer jump in phase.
* Free mode: any rate 0.01–20 Hz, square wave new.

### Found during implementation

* The v1 "sawtooth" table is not a plain saw: it rises over 95 % of the period and
  ramps down over the last 5 % (v1 fix 19, against the reset click). The generated
  saw does the same (rise / fall slopes as constant multiplies), so the legacy
  preset 7 sounds as before and the free-mode saw has no hard reset either.
* The LFO frequency resolution is one phase step, 48000 / 2³² = 11 µHz (5 Hz →
  4.999995 Hz); the sine is within 4.6·10⁻⁵ of `sin()`.

### Removed

The 8 LFO ROM wrappers and their `.mif` tables (`sine_*hz`, `my_sin_10hz`,
`triangle_*hz`, `saw_10hz`, `*_8bit.mif`), and their simulation models.

## D2: interpolated delay lines

### Today

* **Chorus:** a triangle counter moves the delay by **whole samples** (one step
  every 2·(rate+2) samples, between 2 and depth+2 samples). The pitch changes in
  small steps (grainy modulation); rate and depth are in raw units.
* **Echo:** changing `echo_time` moves the read pointer at once: a click.

### New block `mod_delay` (replaces `chorus.vhd`)

```
x ──►(+)──► delay line 2048 × DW (43 ms) ──► 2 reads ─► linear interp. ─► wet ──► mix(dry, wet) ─► y
      ▲                                     d = base + depth·lfo (samples, 8 fraction bits)
      └──── feedback (signed) ◄────────────────────────────────────────── wet
lfo: nco_lfo (D1), bipolar
```

* **Fractional delay:** `d = base + depth · (lfo − 0.5)·2` in samples with 8
  fraction bits. Each sample the line is read at `⌊d⌋` and `⌊d⌋+1` (two reads in
  consecutive clocks: there are 1024 clocks per sample) and interpolated linearly,
  `wet = a + (b − a)·frac/256`. Linear interpolation is enough at these delays
  (the small high-frequency loss is inaudible in a chorus); cubic would need 4 reads.
* **Feedback** (signed, −0.99 … +0.99): the wet signal is added back into the
  line (flanger resonance; negative = hollow flanger).
* **One block, three uses** (only parameter values differ; presets in `gme_hps.py`):

  | Use | Base | Depth | Rate | Feedback | Mix |
  |-----|------|-------|------|----------|-----|
  | Chorus | 15 ms | 3 ms | 0.5–2 Hz | 0 | ~50 % |
  | Flanger (new) | 1–3 ms | ≤ base | 0.1–1 Hz | ±0.5…0.9 | 50 % |
  | Vibrato (new) | 5 ms | 0.5–3 ms | 4–8 Hz | 0 | 100 % wet |

* **Registers** (effect enable bit 4 unchanged). The three old chorus registers get
  clear units, plus three new ones:

  | Reg | Name | Meaning |
  |-----|------|---------|
  | 0x0A | MOD_MIX | dry/wet 0 … 255 (was chorus level) |
  | 0x0B | MOD_DEPTH | modulation depth in samples (0 … base) |
  | 0x0C | MOD_RATE | LFO rate in 0.01 Hz |
  | 0x18 | MOD_BASE | base delay in samples (1 … 2000) |
  | 0x19 | MOD_FB | feedback, signed Q15 (−32767 … 32767) |
  | 0x1A | MOD_SHAPE | LFO shape (0 sine, 1 triangle) |

  Mix, depth, base, feedback and rate are smoothed (no zipper noise when sweeping).
  The v1 meaning of 0x0A–0x0C (Q0.16 level, raw rate divider) is dropped; only our
  own tool used it.

### Echo with interpolation

* `echo_time` goes through the parameter smoother, which already has 8 fraction
  bits: the echo reads at a **fractional** position with the same two-read
  interpolation. Turning the time changes the pitch briefly like a tape echo, without
  a click. Echo line (32 k words) unchanged.

| Test | Check |
|------|-------|
| `test_moddelay` (new) | the block bit-exact to a Python model (interpolation, feedback, mix, LFO) at 16 and 24 bit |
| sweep | an impulse train shows the delay sweeping between base ± depth at the set rate, with sub-sample steps |
| flanger | comb notches move; feedback stable at ±0.99 (no overflow, saturates) |
| echo | sweeping `echo_time` while playing: no step larger than the signal's own (no click); steady delay still exact |

Cost: ~300–500 ALMs, 3–4 DSP blocks; memory unchanged (the 2048-word line
replaces the 1024-word chorus RAM; +1 M10K at 24 bit).

### D2 results (2026-10-25)

* `mod_delay` (chorus / flanger / vibrato): bit-exact to `moddelay_model.py` at 16
  and 24 bit (6000 samples, 8 settings incl. feedback ±0.99 and clamping); a static
  delay of N samples is exactly N samples (independent check). In the chain the
  delay sweeps 41…158 for a set 40…160 and follows a depth change (92…109).
* Echo: fractional read pipeline built so that `echo_frac = 0` is **bit-exact to
  v1** (confirmed against the 27 v1 recordings, incl. the `echo_time = 0` case);
  `test_echo_frac`: half-sample interpolation exact at 16 and 24 bit.
* Registers: 0x16–0x2F became an extension bank (one bus into the core); MOD_BASE,
  MOD_FB, MOD_SHAPE added; mix/depth/rate/base/feedback and the echo time (with its
  fraction) are smoothed. VERSION 0x0204.
* **Reference switch:** after that last v1 check, the v1 recordings, the v1
  reference tests and the simulation-only v1 copies of tremolo and chorus were
  removed. `test_refv2` (31 presets on the 24-bit chain, recorded from the verified
  D2 chain) is the regression anchor from now on; a step that changes an effect on
  purpose re-records only the affected presets after verifying that effect.
* Found on the way: a port named `frac` clashed with the generic `FRAC` (VHDL is
  case-insensitive).

## D3 (preview): cabinet choices

Decided 2026-10-25: **10 cabinets** to choose from.

| # | Source | Licence handling |
|---|--------|------------------|
| 0 | **Default, generated by us** (`tools/make_cab_ir.py`): high-pass ~80 Hz, cabinet resonance ~110 Hz, presence ~2.5 kHz, steep roll-off above ~5 kHz, minimum phase | ours, in git, built into the FPGA image |
| 1–9 | **Free third-party cab IR packs** (WAV), chosen for variety: 1×12 / 2×12 / 4×12, different speakers and microphones. Candidates: Overdriven.fr FB-212 (Zilla 2×12, WGS Vet30), Erik Ekholm "Metal Cabs" (4×12 / 2×12), Signals Audio "God's Cab" (Mesa 4×12 OS), Kalthallen Cabs Free, Origin Effects IR library (6 cabinets / combos) | free to use, but most packs do **not** allow redistribution: the files are **not committed**. Git holds a manifest (name, source URL, licence note, SHA-256) and the conversion script; the WAVs live in `ir/third_party/` (ignored) and on the board |

How they reach the FPGA:

* The FPGA has **two coefficient banks** (2048 taps × 18 bit each, 42.7 ms at 48 kHz):
  one plays while the other is loaded, then a crossfade switches cabinets
  without a click. At power-up bank A holds the default IR (no Linux needed).
* `tools/ir_convert.py` (PC or board): WAV (16/24/32-bit, 44.1/48/96 kHz) →
  48 kHz, trimmed to 2048 taps with a short fade-out, level-normalised so all
  cabinets play at the same loudness → `.npy`/`.bin` coefficient file.
* On the board: `/home/root/gme/ir/0..9` and `gme_hps.py cab 3` (load + switch),
  `gme_hps.py cab list`. More than 10 can be added later; 10 is the starting set.

### Done ahead of the RTL (2026-10-25)

* `tools/make_cab_ir.py` generates cabinet 0 (`ir/cab00_default.wav`): +4 dB at
  110 Hz, −3.5 dB at 400 Hz, +4 dB at 2.5 kHz, −18 dB at 8 kHz (relative to 1 kHz).
* `ir/manifest.json`: the 10 cabinets (0 default; 1–8 from "25 Analog Cab IRs":
  1x12 American / British, 2x12 Blackface / VC 30, 4x10 American, 4x12 British /
  Metal American / Metal British; 9 Overdriven FB-212 Vet30 SM57), with source,
  licence note and SHA-256. Third-party files stay in `ir/third_party/` (ignored).
* `tools/ir_build.py` (shared code in `tools/cabir.py`, numpy only): reads any WAV
  incl. WAVE_FORMAT_EXTENSIBLE, resamples 44.1 → 48 kHz, trims to 2048 taps,
  equal loudness (pink-weighted 80 Hz–8 kHz), quantises to 18 bit; writes
  `ir/build/` (ignored): `cabNN.bin/.txt`, demo WAVs (distorted lick through each
  cabinet, one common gain), `responses.svg`, `report.txt`.
* Finding for the RTL: after equal-loudness scaling the largest coefficient is only
  0.05–0.12, i.e. a plain Q1.17 format would leave 3–4 bits unused. The FPGA will
  store each cabinet **scaled to full range plus a per-cabinet output shift**
  (block floating point). Worst-case gain Σ|h| is 1.4–3.1 (+3…+10 dB): the FIR
  output saturates.

### D3 RTL design

```
dist_out ──┬────────────────────────────────────────────── (cab off: no extra latency)
           └─► history RAM 2048 × DW ─┐                         │
                coef RAM bank A/B ────┴─► 4 MAC lanes ─► Σ ─► × 2^-shift ─► sat ─► wet (+1 frame)
                (2 × 2048 × 18, HPS-writable)                    └─► fx crossfade ─► chorus
```

* **Where:** between distortion and chorus (amp → cabinet → mic → time effects).
* **Time budget:** one frame is 1024 clocks; the FIR starts after the sample_tick
  update of the distortion output and must finish before the next one. 2048 taps
  with **4 MAC lanes** (each lane its own 512-word slice of history and
  coefficients, one 24 × 18-bit DSP multiply per clock) take 512 + ~8 clocks. The
  wet output is registered at the next sample_tick: **+1 frame latency** when the
  cabinet is on, none when it is off (the bypass is a plain connection, so all other
  presets keep their latency and the v1 references stay bit-exact).
* **Accuracy:** 42-bit products, 53-bit accumulator, one rounding at the end:
  `wet = sat(Σ h·x >> (17 + shift))`. `shift` (0…7, per cabinet) restores the
  coefficient scale: the build tool stores every IR scaled to full 18-bit range
  (block floating point, see "Done ahead of the RTL").
* **Two coefficient banks:** the HPS writes the inactive bank (registers
  CAB_ADDR with auto-increment, CAB_DATA_LO / CAB_DATA_HI; the per-bank shifts are in
  CAB_CTRL), then CAB_CTRL switches banks. The switch is click-free without computing two FIRs:
  the wet level fades out over 128 samples, the bank switches, and it fades back in
  over 128 samples (dry stays on, so it is a 5 ms dip of the cabinet sound only).
* **Power-up:** bank A initialised with cabinet 0 (generated `.mif`), so the cabinet
  works without Linux. Effect enable bit 6 (CAB), level-matched wet.
* **Simulation:** generic `CAB_TAPS` (2048 in the FPGA). The FX_chain tests use
  16 taps so the FIR fits the 16-clock frames of the fast frame driver; `test_cabfir`
  runs the FIR block alone, the full 2048 taps with 1024-clock frames, bit-exact to a numpy
  model (convolution, rounding, saturation, bank switch), and `test_system` runs the
  whole design with the 2048-tap default cabinet.

### D3 implementation and results (integrated 2026-10-25)

Files: `cab_fir.vhd` (the FIR, see its header), `cab_coef_ram.vhd` (Intel altsyncram, simulation twin in
`sim/models/`), `cab_stage.vhd` (FIR + fades + write protection, instance `CAB_left` in `FX_chain`),
`fpga/ip/cab_default.mif` (cabinet 0, 2 × 2048 words), `tools/cab_coefs.py`.

* **Position / bypass:** `FX_chain`: Overdrive → Distortion → **Cabinet** → Chorus → Tremolo → Echo → Reverb,
  enable bit 6. The stage output is `dout = din + floor((wet − din)·g / 256)` with `g` = 0 … 256,
  **combinational from `din`** (not `fx_xfade`, whose dry path is registered): with the cabinet off
  (`g = 0`) the output is exactly `dist_out`, so latency and all `test_refv2` references stay unchanged
  (`test_refv2` passes without re-recording); `g = 256` gives exactly the FIR output.
* **Strobe:** `start` = `sample_tick` delayed by one clock (the distortion output has been updated by the
  `sample_tick` edge); the FIR runs on every sample, also when the cabinet is off (warm history). Its output is
  one sample late and valid from `start` to the next `start`, long before `half_tick`, when the chorus samples it.
* **Fades:** `g` moves once per `sample_tick`: ±1 for enable / disable (256 samples). **Bank change**
  (`CAB_CTRL` bit 0 ≠ the bank in use): `g` runs down in steps of 2 (128 samples), at `g = 0` the bank in use
  (and with it the shift) switches, `g` runs back up in steps of 2 (128 samples) if the cabinet is enabled.
  `XFADE = false`: `g` and the bank jump.
* **Write protection:** `cab_stage` forwards a coefficient write only when `cw_bank` is neither the bank in use nor
  the requested bank; writes to the active bank (including both banks while a switch is running) are dropped.
* **Register side effects:** `ctrl_avmm` gives a 1-cycle strobe (`ext_we`) with the register number and the complete
  value for every write of 0x16 … 0x2F that contains byte 1 (like CODEC), one clock after the write, when the
  register already holds the new value. `gme_core` keeps the 12-bit pointer: CAB_ADDR (0x1C) loads it;
  CAB_DATA_HI (0x1E) writes `{HI[1:0], CAB_DATA_LO}` at it (registered `cab_cw_*` port of `FX_chain`) and increments
  the tap address (bank bit unchanged). The registers 0x1B … 0x1E are ordinary R/W registers (read back what was written).
* **Constraints:** `top_v2.sdc` adds `*|u_fx|CAB_left|*` to the per-clock blocks (`seqblk`) that are excluded from the
  16-cycle multicycle relaxation: the FIR pipeline and the crossfade keep single-cycle constraints (the crossfade is
  a combinational path from the distortion output to the chorus input, checked with the full 20 ns).
  `top_v2.vhd` passes `CAB_INIT => "ip/cab_default.mif"` (Quartus looks for the `.mif` relative to the project, the
  simulation finds `cab_default.mif` in its working directory).
* **Board tool:** `gme_hps.py cab list | cab N | cab on | cab off`; `tools/cab_coefs.py --build` writes
  `ir/build/cabNN.coef` for every manifest slot whose IR file is present (name, shift, 2048 integers; git-ignored).
  Loading writes the idle bank (4096 register writes), then CAB_CTRL.
* **Version:** 0x0205.
